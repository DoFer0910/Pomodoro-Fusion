# 開発中のPro機能と無料版の確認

配布版の自動更新・初回導入・無料版とPro版の更新先は [アプリの配布と自動更新](app-updates.md) を参照する。Pro版は無料版の更新先をそのまま使わず、専用配布先を指定する。

アプリ本体の編集・日常の開発は `D:\Dev\ポモドーロ` で行う。通常開発は全Pro機能を使えるため、プロジェクト数やCSV出力の制限で開発を止めない。

| 用途 | Web | Electron |
|---|---|---|
| 全機能を使って開発 | `npm run dev` | `npm run dev:electron` |
| 無料版の制限を確認 | `npm run dev:free` | `npm run dev:electron:free` |

起動中のサーバー・開発アプリを終了してから、別のモードで起動する。無料版確認では新規プロジェクトは3件まで、CSV出力は利用できない。上限を超える既存プロジェクトを削除することはない。

通常開発の設定画面には「開発用：Pro機能を解放中」と表示する。ライセンス鍵の発行・入力・保存は不要で、解放状態も保存しない。モードは起動時に決まり、アプリ内の解除ボタンでは切り替えない。

## 配布版への混入を防ぐ仕組み

`lib/license.ts` は `NODE_ENV === "development"` のときだけ開発用のPro状態を返す。`NEXT_PUBLIC_YIELD_DEV_PLAN=free` は無料版確認用で、未設定または `pro` は通常開発用。不明な値は無料状態になる。

`npm run build` と `npm run build:electron` で作るpublic配布版は常に無料状態になる。Next.jsが本番ビルド時に開発経路を無効化するため、開発用の環境変数が残っていてもProにはならない。ストレージやURLから開発用の解放は指定できない。

単体テストで起動条件・鍵の扱いを、E2Eで実際のプロジェクト追加・CSV出力を検証する。`npm run ci` は開発用設定を残した本番ビルドの無料状態に加え、実際の開発サーバーを通常開発・無料版確認で順番に起動して確認する。開発モードだけのE2Eは `npm run test:e2e:license`。

## 販売用Pro版への反映

`yield-pro` はアプリ本体を `public/` submoduleとして取り込み、署名検証をする `pro/lib/license.ts` に差し替えて販売版を作る。署名検証・課金方式は今回変更しない。public側の開発用解放は販売用の実装へ差し替えられる。

1. ポモドーロ側の変更をテストし、PRをマージしてpushする。
2. `D:\Dev\yield-pro` の `public/` に未コミット変更がないことを確認する。Pro実装を注入したままなら、ライセンスファイルに必要な編集がないことを確認してから `npm run restore-public` で戻す。
3. `git -C public fetch origin` で取得し、レビュー済みのコミットを `git -C public checkout <commit>` で選ぶ。
4. `git diff --submodule=log` で取り込む変更を確認し、`public/` の参照更新をyield-pro側でコミットする。
5. `npm run build:pro` で販売版を作り、正式なライセンスによる解放を確認する。

取り込むコミットを明示することで、販売版にどの機能・修正が入ったかを追跡できる。開発中の変更はポモドーロ側で直接確認し、販売版の組み立て時に反映する。
