# 勤務記録

## 時間の扱い

「勤務記録」は本人が仕事をしていた時間を記録する画面です。ポモドーロの集中時間やAIのログとは独立しています。AIの並行利用やツールの待ち時間で、勤務時間が自動的に増減することはありません。

仕事を考える・資料を読む・結果を確認する時間も含め、会社の申告基準に沿って本人が確認します。食事や私用など仕事から離れるときは「休憩に入る」か「勤務終了」を操作します。無操作だけで休憩とは判断しません。

従来の「統計」「履歴」「CSV」は従来の作業セッション・AI収益集計です。勤務時間を転記するときは、新しい「勤務記録」の確認済み一覧を使います。過去の作業セッションを勤務記録へ自動変換する処理はありません。

## 普段の操作

1. 「勤務記録」で案件を選び、「勤務開始」を押します。案件は未選択でも記録できます。
2. 仕事から離れるときは「休憩に入る」、戻ったら「勤務再開」を押します。
3. 勤務中に別の案件へ移る場合は案件を選び、「このプロジェクトに切替」を押します。前の区間を終了して次の区間を開始します。
4. 仕事を終えたら「勤務終了」を押します。タイマー画面にも勤務の操作ボタンがあります。コンパクト表示の勤務状態を押すと通常表示の勤務記録に戻れます。
5. 日付を選び、本人の勤務・休憩とAI参考履歴を確認します。開始忘れや終了忘れは区間の追加・編集で直します。
6. 確認が済んだら「この日の記録を確定」を押します。未終了の区間がある日は確定できません。確定後の時刻変更や削除では、その日の確認が解除されます。
7. 「確定した日別時間をコピー」で日付と勤務時間を転記できます。形式は `日付<TAB>時間:分:秒` です。秒は保持します。freeeへの送信や丸めは行わず、転記時に必要な単位を確認します。

日をまたぐ区間は、端末のローカル日付の境界で日別に集計します。実際に記録した休憩だけを集計し、ポモドーロ設定の休憩時間を一律に引きません。

## 開始忘れとAI参考履歴

デスクトップ版では起動中に30秒間隔でClaude CodeとCodexのログを確認します。プロジェクトのリポジトリパスへ、AIで使用する作業ディレクトリを登録してください。別のworktreeで作業する場合は、そのパスも登録します。

勤務記録が止まっているときに新しいログが見つかると、アプリ内の候補とデスクトップ通知を表示します。候補からの勤務開始、現在からの開始、勤務に含めない判断、後での確認を選べます。同じイベント区間で通知を繰り返しません。起動時に読み込んだ過去のログは通知せず、日別画面から確認できます。

参考履歴の時刻は実際のログイベントの時刻です。5分以上途切れる箇所では参考区間を分けますが、その間に本人が休んでいたとは判断しません。AIが連続して動いていた時間も保証しません。累積秒数を開始時刻へ足して終了時刻を作ることはありません。プロンプトやログ本文は保存しません。

「時刻を確認して追加」は、参考区間を本人が確認・修正して勤務記録にする操作です。「勤務に含めない」の判断は保存され、後から取り消せます。勤務外の判断を変更すると、影響する日の確認も解除されます。

ブラウザ版ではAIログを取得できませんが、勤務の計測と手動追加は使えます。ログ取得に失敗した場合は前回の参考履歴とエラーを表示し、再確認できます。AIログの取得・失敗だけで本人の勤務データは変更されません。

## データ保護

- 勤務・休憩区間は実時刻で記録し、終了前の区間も保存します。アプリ再起動時の未終了区間は確認を促します。自動で確認済みにはしません。
- 不正時刻、未来の区間、終了が開始以前、他の勤務・休憩との重複を拒否します。
- 保存に失敗した編集内容はダイアログに残ります。再試行してから閉じてください。
- プロジェクト削除後も時刻と案件名のスナップショットを保持します。
- 勤務データは `yield-attendance` に保存し、作業セッションとは別に書込みを直列化します。
- バックアップ形式v3には勤務区間、勤務外の判断、日別の確認状態を含めます。旧v2以前のバックアップを復元すると、勤務データは空の状態として復元されます。勤務データが不正なバックアップは、既存設定の上書き前に拒否します。

## 開発・検証

`npm run ci` は現行アプリの型チェック、Vitest、静的ビルド、Playwright E2Eを実行します。旧アプリの `legacy_app_v1` は独立した旧実装のため、現行アプリの型チェックから除外します。

E2Eでは本人の勤務の代表操作と、実際のテスト用ログファイル→スキャナーのワーカー→Electron IPC→画面→electron-storeの保存を通します。Electronテストはテスト専用ディレクトリを使用し、普段利用しているアプリの保存データやAIログにはアクセスしません。ログスキャナーの結果をモックで置き換えません。

初回の大量ログ読み取りはワーカーで処理し、Electronの画面やウィンドウ操作を止めないようにしています。以降はログの更新時刻とサイズによるキャッシュを利用します。
